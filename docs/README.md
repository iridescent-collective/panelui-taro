# PanelUI Taro documentation

A Next.js App Router + Fumadocs site for the Native-derived Taro/WeChat library. Its notebook layout, neutral palette, navigation and homepage structure follow the upstream PanelUI site. It retains the upstream MIT license and attribution in `UPSTREAM-LICENSE` and `UPSTREAM-NOTICE`.

## Run

From the workspace root:

```sh
pnpm install
pnpm dev:panelui-docs
pnpm build:panelui-docs
pnpm typecheck:panelui-docs
pnpm --filter panelui-docs start
pnpm --filter panelui-docs verify
pnpm --filter panelui-docs verify:standalone
```

The local address is http://localhost:3100. `verify` checks the running production server; set `PANELUI_DOCS_URL` to check another deployment.

## Content and generation

Handwritten English and Simplified Chinese guides live in `content/docs`. The component reference is generated by `scripts/generate-docs.mjs` from the library's public exports, source type declarations, source inventory and WeChat example metadata. It does not require the upstream checkout, business environment files or credentials.

`content/docs/components/` and `lib/catalogue.json` are generated at install, dev, typecheck and build time. They are ignored by Git, together with `.next`, `.source` and TypeScript caches. Edit the component source or example metadata rather than generated reference files.

The homepage demonstration is a web illustration. Actual Taro components and native capabilities run in `example`, not inside this website. The site does not import `panelui-web` or a React Native runtime.

## Dependencies

Named `panelui-*` catalogs in the root `pnpm-workspace.yaml` use caret ranges. The lockfile records the verified installation. The site uses React 19; the mini program uses React 18. The library owns the shared Vitest 5 / Vite 8 test runner, keeping the example's Taro Vite 4 build independent. PanelUI tooling uses the TypeScript 6 catalog.

## Deployment

If Vercel’s automatic monorepo change detection is enabled, disable skipping unaffected projects for this site: the generator reads the library source directly rather than importing it into the web runtime. A library source change must rebuild the documentation.

For Vercel, use this monorepo with `docs` as the project root, include files outside the root directory, and run `pnpm build:panelui-docs` from the repository root or the package's build script from its project directory. The generator reads the library at the repository root, so uploading this app folder alone is insufficient.

The local start command defaults to loopback. Set `HOSTNAME=0.0.0.0` in a container or remote deployment.

For self-hosting, `next build` creates `.next/standalone`. Copy `public` and `.next/static` beside the generated app server before starting it. Follow the generated monorepo directory structure. Markdown is embedded at build time; the export endpoint does not require MDX source files at runtime. Search runs in the Next server. This configuration is not a static OSS-only export.

The library remains private. Publishing it requires authorization and fresh-consumer compatibility checks.

## Internationalization

English uses `/en`, and Simplified Chinese uses `/zh-CN`. Existing unprefixed URLs permanently redirect to the corresponding English page; the URL determines both server rendering and hydration, with no browser-only language detection. The Fumadocs switcher retains the document, query and fragment. Refreshing or sharing a link retains its language.

Keep `locales/en.json` and `locales/zh-CN.json` translation keys aligned. Handwritten guides use paired `.mdx` and `.zh-CN.mdx` files; component references are generated in both languages. Code identifiers, API types and official variant names remain unchanged.

Search, Markdown exports and internal links follow the current locale. Set `NEXT_PUBLIC_SITE_URL` before building so canonical and alternate-language links use the deployed domain.

Run `pnpm --filter panelui-docs test:i18n` and the production HTTP verifier after changing translations or routes. Follow [i18next instance guidance](https://www.i18next.com/overview/api), [react-i18next SSR](https://react.i18next.com/latest/ssr) and [Fumadocs i18n routing](https://www.fumadocs.dev/docs/internationalization/next).
