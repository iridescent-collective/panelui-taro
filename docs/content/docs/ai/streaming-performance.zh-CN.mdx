---
title: "流式性能"
description: "限制界面更新频率，并区分自动化检查和设备测量。"
---

真实服务驱动把事件合并为每 50 ms 一次 React 更新，不按每个网络分块触发渲染。完成、失败和停止时立即刷新待显示内容；清理时取消待执行定时器。本地演示仍使用独立的 100 ms 预置回复定时器。

ChatTurn 使用 memo。不可变更新保留其他消息对象，只给最后一条传入忙碌状态。流中相邻正文合并为一个片段，工具调用保留原始位置，来源单独汇总。

MessageScroller 沿用现有 Taro 滚动实现。Native 的反向 FlatList、屏幕外列表项回收和 Reanimated UI 线程执行，不能通过更换组件名直接复制到微信。长会话仍需设备测量，不声称内存恒定或帧率已经改善。

## 限制与失败处理

客户端限制单次响应不超过 1 MiB，单行事件不超过 256 KiB。服务端限制请求、上游事件、工具参数、并发数和输出大小。UTF-8 截断、非法事件或缺少终止事件的断流会明确报错；中文和 emoji 可以跨任意网络分块解码。

## 验证

在仓库根目录执行：

```sh
pnpm test:panelui-example
pnpm --filter panelui-example test:ai-server
pnpm --filter panelui-example typecheck
pnpm build:weapp:panelui
```

自动化覆盖字节边界、整包回退、异常断流、取消、延迟回调和更新合并。服务端测试使用本地假供应商，不调用付费模型。设备验收另行记录长会话、持续生成、键盘、用户滚动位置、停止与重试、浮层、前后台切换，以及 iOS/Android 帧表现。
